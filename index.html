Know sooner.

TUnit is a testing framework for modern .NET. It checks your tests as you type, finds them as you build, and runs them the way you describe.

Get startedWhy TUnit?

As you type

Mistakes show up in the editor.

Analyzers read your tests while you write them. A forgotten await, a hook with the wrong signature or a data source that doesn't fit its test is flagged in the editor, before anything runs.

Awaiting assertions

As you build

Your tests are found by the compiler.

A source generator writes the code that registers every test while your project builds. Nothing scans assemblies with reflection at startup, so the first test starts straight away, and test projects can publish with Native AOT.

Native AOT support

As it runs

Say how your tests relate. TUnit schedules the rest.

Tests run in parallel unless you say otherwise. When some of them share a database, need an order or would swamp a service, one attribute says so. Switch them on and watch the same run rearrange.

Control parallel execution

As it grows

From one method to the whole system.

The same framework drives integration tests, with shared infrastructure that starts once and is cleaned up after the last test using it finishes. One test method can also become many cases, fed from attributes, methods, classes or a matrix of values.

  2. >dotnet new TUnit -n MyTests
  3. >dotnet run --project MyTests
